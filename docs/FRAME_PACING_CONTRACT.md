# FP: вывод кадра без изменения физики

2026-10-08, baseline 4ed22ef. Задача: FPS, сохранить принятую тягу и тепло.
Изменение только расписания Update/Draw/Present, не поведения веществ.

Исходно обычный запуск: variable timestep и VSync=true. На копии печи
968×564, 2560×1440, датчики включены: отключение VSync даёт около230FPS
вместо69–74; физическое время≈1×, воздух/газ/реакции60Hz, тепло20Hz.
Это измерение диагностического окна, пользовательские32FPS пока не повторены.

Выбранный контракт: обычный запуск VSync=false, потолок100FPS отдельным
ожиданием после Present. Никакого пропуска физического времени, изменения
числа итераций, шейдеров, частот, масштаба или эффектов. Под нагрузкой
ожидание сокращается до нуля; не догоняем пропущенные кадры серией рендеров.
Windows high-resolution waitable timer, без busy spin; безопасный fallback
при отсутствии high-resolution timer. Диагностические ускоренные прогоны
и собственные schedulers не получают второй limiter. Ресурсы освобождаются.

До принятия: парные30с replay старого VSync/нового pacing, новый без
ограничения отдельно; FPS, p95 времени кадра, CPU Present/ожидание, физический
ход времени и ticks. Пауза не создаёт физические ticks. Свежая проверка печи,
тяги/температур и save/load. Пользовательские файлы не перезаписывать.
Оптимизация не обещает100FPS на любом мире/GPU и может допускать tearing
при непосредственном выводе без синхронизации. VSync можно вернуть через
диагностический override; длительный обычный игровой сеанс пока не измерен.
