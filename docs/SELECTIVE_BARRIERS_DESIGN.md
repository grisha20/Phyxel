# Избирательно проницаемые стенки — задел

2026-10-05. Пользователь просит основу будущих инструментов как в TPT:
стенка, пропускающая газы и задерживающая жидкости, либо пропускающая воду
и задерживающая пламя. Готовая модель правил:
`Core/SelectiveBarrierPolicy.cs`; проверка в `AbsorptionModelRegressionVerifier`.
В интерфейсе новых стенок пока нет; это не заявляется реализованной физикой.

TPT `Simulation::IsWallBlocking`, `simulation/Simulation.cpp`1080–1097:
WL_ALLOWGAS/WL_ALLOWLIQUID/WL_ALLOWPOWDER проверяют TYPE_GAS/TYPE_LIQUID/
TYPE_PART. Фоновый воздух использует свою карту стен. Эти группы не означают
конкретную воду и не отличают пламя от остальных газов. У Phyxel пламя —
flag Flame; правило может исключить его отдельно.

Правило содержит разрешённые виды движущихся частиц и стабильные ID,
отдельный запрет Flame, отдельную проницаемость воздуха/O₂ и тепла.
Preset GasOnly пропускает газы и фоновый воздух, задерживает жидкости/порошки.
Preset WaterOnly пропускает только core:water, задерживает масло, пар и пламя;
фоновой воздушной связи нет. Оба preset пока допускают тепло: задержка
частиц огня не гарантирует отсутствие нагрева/поджига по другую сторону.
Для теплоизоляции AllowsHeat=false должен быть отдельным явным выбором.

Будущая интеграция обязана:

1. Хранить стенку в отдельном overlay мелкой сетки. Прошедшая частица
   сосуществует со стенкой; нельзя заменять материал стенки жидкостью.
2. Переводить стабильные ID в разрешения GPU после загрузки каталога;
   закрыто по умолчанию для неизвестного вида, никакой привязки к RuntimeIndex.
3. Проверять всю пересекаемую траекторию во всех путях воды/гидравлики,
   вязкой поверхности/слоёв, падения/скатывания, газа/диффузии и движения тел.
   Удалённый гидравлический перенос не должен перескакивать фильтр.
4. Применять отдельные face-разрешения к полям воздуха, O₂ и тепла,
   включая обмен с поверхностью. Передача жидкости по порам — отдельный путь,
   который тоже должен учитывать overlay; проницаемость не даёт поглощения.
5. Сохранять overlay/rule palette в отдельной секции мира, поддержать кисть,
   ластик, resize/expansion, паузу/reload и отображение без эффектов.
6. Проверить проток/задержку каждого класса, газ/fire отличие, воду/oil/steam,
   сохранение массы/Q, обе модели горения и углы/стыки/толстые стенки.

CPU-правила сейчас проверены по всему каталогу, включая специально
зарегистрированную негорючую жидкость. GPU overlay и инструменты в панели
остаются будущим этапом; поглощение liquids от них не зависит.
