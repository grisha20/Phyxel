## 1. Точный источник HotAir

TPT задаёт давление как свойство материала:

| Элемент TPT | Файл | `HotAir` | Вклад за частицу |
|---|---|---:|---:|
| WTRV | `simulation/elements/WTRV.cpp:21` | 0.0003 | 0.0012 |
| FIRE | `simulation/elements/FIRE.cpp:25` | 0.0010 | 0.0040 |
| SMKE | `simulation/elements/SMKE.cpp:21` | 0.0010 | 0.0040 |

В `Simulation.cpp:2344-2353` TPT применяет множитель `4 * HotAir` при
впрыске в coarse pressure field. Phyxel теперь хранит это в
`MaterialProperties.HotAir`: `steam.json = 0.0003`, `fire.json = 0.001`,
`smoke.json = 0.001`. `CSInject` применяет ровно `4 * material.HotAir` на
каждую занятую газовую клетку. Поэтому FIRE и SMKE сохранили прежние
`0.004`, а WTRV впервые получил свой TPT-источник `0.0012`.

Layout material table расширен синхронно в C# и HLSL: 160 -> 176 байт,
41 семантическое поле и 3 scalar padding-поля. Диагностика подтверждает:
`PHYXEL_MATERIAL_PROPERTIES_LAYOUT csharpActual=176 hlslDeclared=176
fields=41 match=1`. Старые material JSON безопасны: отсутствующее
`gas.hotAir` подставляет `0` (это проверяется на `core:co2`). Сохранённые
миры не содержат `MaterialProperties`, а сериализуют только `GridCell` с
фиксированным размером 40 байт; загрузка старого формата поэтому не менялась.

### Контроль огня

Включение WTRV не изменило FIRE/SMKE: `fire_open` остаётся
`VelocityY = -1.914 ± 0.015`, фактический подъём `1.328 ± 0.001`; на

## 3. Метрики, которым нельзя верить

| Ошибочная метрика / метод | Почему неверна |
|---|---|
| `obstacleCoverage = maxX - minX` | Одна одиночная клетка у края даёт почти 100% покрытия при массе в центре. |
| `sigmaX` по 13 клеткам | Слишком малая выборка; шум выборки выше эффекта. |
| Кадр 600 при `clippedTop=1` | Верхняя граница мира сжимает облако и искажает форму/скорость фронта. |
| Сравнение миров разной высоты | Струя получает разную дистанцию разгона. |
| σ по 4--5 свежим клеткам | Относительная ошибка около 32%; вывод о форме источника невозможен. |
| Air-профиль вне занимаемых газом coarse-клеток | Он измеряет дальнее поле, а не поток, который фактически читает газ. |
| PNG `steam_obstacle` до исправления | Снимки сохранялись под именами `AA_steam_jet_*`, поэтому сравнение с `artifacts/steam-obstacle-hotair-baseline` сопоставляло разные сцены, а не разные состояния одной сцены. Исправлено в `8e405c5`: теперь используются `AA_steam_obstacle_300/600/1200`. |

## 4. Отвергнутые гипотезы

| Гипотеза | Результат |
|---|---|
| Конвекция Boussinesq — источник ошибки одиночного puff | Нет: air-off уже совпадает с собственной плавучестью, а абляция не объяснила форму. |
| `motion.airDrag` создаёт весь разгон пара | Нет: абляция не свела скорость к air-off. |
| Отражение заблокированного газа расширит ствол | Нет: `sigmaX` в стволе не достиг 6.0, а стоимость для движения высока. |
| Атомарный диагональный ход — недостающий механизм | Нет: направление не дало требуемого роста `sigmaX`. |
| Геометрия fixed-inflow уже была сконцентрирована к оси | Нет: накопленная выборка показала равномерный диск. |
| Только величина fixed-inflow объясняет расхождение | Нет: она маскирует связь между обычной кистью и притоком. |
| Мир 1920x1080 сам создаёт различие | Нет: 612x384 не устранил избыток скорости. |
| Кисть Phyxel была меньше TPT | Нет: TPT radius 8, проверка radius 8 в Phyxel не сняла расхождение. |

## 5. Открытые вопросы

1. Свободная струя всё ещё быстрее: 1.221 клетки/кадр против TPT 0.55.
2. Контактный слой пара всё ещё слишком плотный: 34.6% с обычной кистью
   (41.7% в предыдущем fixed-inflow baseline) против TPT 6.6% на кадре 1200.
3. Тепло и конденсация не являются частью этого изменения: температура METL
   к 1200 кадру около 59--60 C против 91--93 C TPT, вода остаётся у дна.

Эти пункты не следует исправлять подбором коэффициентов HotAir: значение
WTRV уже взято напрямую из оригинала.
