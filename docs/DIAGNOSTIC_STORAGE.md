## Инструмент

Из корня проекта, PowerShell:

```powershell
# Только список категорий, количество и размер; ничего не удаляет.
./tools/Clear-DiagnosticArtifacts.ps1

# Удаление проверенных категорий с журналом вне репозитория.
./tools/Clear-DiagnosticArtifacts.ps1 -Apply
```

Инструмент работает только с `artifacts/` данного checkout. Перед удалением
проверяет отсутствие tracked-файлов и reparse points, проверяет абсолютный
путь каждого файла, его размер и время изменения. Удаляет только файлы;
папки удаляются лишь после опустошения, без рекурсивного удаления каталога.
При работающем Phyxel применение запрещено.

Удаляемые категории:

- сырые диагностические `.bin`, `.grid`, NumPy-кеши;
- старые тестовые runtime-файлы/шейдерные пакеты/архивы внутри `artifacts/`;
- тестовые `.world` с известными именами regression-сценариев;
- промежуточные нумерованные PNG каждой серии; первый и последний остаются.

Сохраняются код, скрипты, JSON/CSV/логи/текстовые отчёты, ненумерованные
изображения, входные `source`/`original`/`inputs`/`fixtures`, источники
карточек/оформления и неизвестные сохранения. За пределами `artifacts/`
ничего не удаляется: `scenes/`, `%LOCALAPPDATA%/Phyxel`, Git, Content,
актуальные `bin/Debug` и `bin/Release` не являются целью инструмента.
Для неизвестного старого файла сначала установить назначение; одно
попадание в `.gitignore` не означает, что он бесполезен.

Журнал путей/размеров и итоговый счётчик находятся в
`%LOCALAPPDATA%/PhyxelDiagnostics/cleanup-YYYYMMDD-HHMMSS/`.
При успешном завершении `removed-files.csv` соответствует удалённым файлам;
при ошибке/прерывании это список запланированных файлов, итогового
`summary.json` нет. Исходные файлы автоматически не восстанавливаются.

## Следующие проверки

Перед серией оценивать `ширина × высота × размер клетки × число снимков`.
При1920×1080 один Grid56 занимает116MiB; десятки повторных прогонов быстро
дают десятки GiB. Для итогового отчёта обычно достаточно метрик, нескольких
кадров и исходной сцены. Полные поля сохранять только на интервале ошибки
либо для конкретного побайтного сравнения; затем удалять промежуточные
файлы после фиксации вывода. Перенос на другой диск не решает накопление.

Исторические документы могут ссылаться на удалённые промежуточные снимки
в `artifacts/`. Текстовые измерения/протоколы остаются, но наличие старого
PASS не означает, что весь сырой набор после очистки сохранён. Для нового
сравнения заново воспроизвести нужную версию и сценарий. Новые каталоги
диагностики наC этой очисткой не затрагивались.
