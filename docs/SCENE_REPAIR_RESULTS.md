# Сохранение остатков и исправления фильтров — 2026-10-05

Исправлен воспроизведённый отказ сохранения пользовательской сцены.
Grid, MaterialProperties и формат v17 прежние (56/244 байта); добавлен
флаг non-absorbable-liquid bit14 без расширения таблиц. Паспорта каталога
целиком не закрываются этим результатом.

## Причина и поведение

Из процесса пользовательской игры извлечены оставшиеся CPU-массивы GPU
readback, 672×394. В позднем Grid 114 активных клеток превышают текущую
вместимость: основа пороха/угля уменьшилась, а удержанный molten_metal
остался. Старый SaveAsync на этом же массиве воспроизводит
`Absorbed fuel is unsupported or exceeds shared pore capacity.` до
создания JSON. Артефакт ошибки: [old-save-failure.txt](../artifacts/live-save-diagnostic/old-save-failure.txt).
Другая причина остановки пороха: прежний ограничитель оставлял .0002
основы, пока есть любой запас жидкости. Негорючий расплав не расходуется
реакцией пропитки, поэтому остаток оставался навсегда.

По уточнению пользователя новый расплав металла не поступает ни в один
из пяти пористых материалов и не распространяется из старых пор. Общий
флаг применим к будущим металлическим расплавам и другим исключённым
жидкостям, включая основной канал влаги. Масло/вода по-прежнему впитываются.
Сохранённый ранее вид/масса не удаляются при чтении. Усохшая горючая основа
может удержать свой старый конечный запас; новый приток ограничен текущей
вместимостью. После полного выгорания без остатка жидкость занимает ту же
клетку с той же массой и энтальпией; при wood→coal остаётся в остатке.
[Контракт и границы](materials/shared/BURNOUT_STOCK_CONTRACT.md).

ПКМ кисти фильтра теперь использует обычный Erase: стирает частицы и слой.
ЛКМ по-прежнему защищает занятые клетки. Exact-ID окрашены по веществу,
групповые режимы имеют свои цвета. Семантически одинаковый exact-ID из
разных карточек имеет одинаковый цвет. Ошибка сохранения теперь показывает
причину и пишет исключение в stderr, а не только имя выбранного файла.

## Границы результата

Ответ нативного диалога в автоматизации подменён, сама запись и игровые
обработчики настоящие. Поля воздуха/реакций первоначальной пользовательской
сцены не связаны достоверно с конкретным извлечённым Grid: восстановленный
`recovered-grid.json` — диагностическая копия клеток, не полное восстановление
исходной динамики или фильтров. Картинки пользователя показывают также
режим с расходом O₂; температура/свечение не доказывают активное горение.
Полный прогон исходной закрытой сцены не объявляется PASS.

Выход жидкости в соседнюю клетку во время усадки, поровые фазы, сплавы и
химия металлических расплавов не добавлены. Запись двух файлов не стала
атомарной. Для нового найденного дефекта сохраняйте JSON и соседний WORLD
в отдельное имя; предоставляйте оба файла или путь к JSON на этой машине.
