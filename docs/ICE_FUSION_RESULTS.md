# Лёд ↔ вода: теплота плавления

2026-10-03. Phyxel HEAD `0583f2a` + рабочая копия; NVIDIA RTX4070.
Область: энергетический переход лёд/вода, сохранение прогресса и связанные
тепловые регрессии. Полный паспорт льда и весь этап1 каталога не завершены.

## Изменение

Оба порога0°C. Лёд накапливает333.4 нормированных единицы энергии/массу
перед превращением в воду; замерзание отдаёт столько же. Частичный переход
держит0°C, обращается охлаждением/нагревом, переносится вместе с жидкостью.
Избыток тепла сохраняется в новой фазе. Прежняя ветка вода/пар сохранена.

Новый opt-in `fusion-enthalpy` работает для проверенной обратимой пары
solid/liquid. `Lifetime`: у льда положительный прогресс плавления; у воды
отрицательный прогресс замерзания и положительный прогресс кипения.
Writer scene/worldv11; header28/Grid40/material176 не увеличены.
Старыеv3–v10 читаются. Отрицательные значения в старых форматах и на дыме
отклоняются. Металл/расплав этим этапом не изменён.

Физический ориентир333.4 J/g для льдаIh при0°C/101.325кПа:
[NIST, Harvey, Properties of Ice and Supercooled Water](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=926353).
Согласование с c2.10/4.18 и Lvap2256 задаёт игровую шкалу, не СИ-калибровку
клетки. В TPT ICEI.HighTemperature252.05K — специальный ST-вход; общий
обработчик для ctype=WATR требует273.15K. Коэффициенты TPT не копировались.

## Сравнение с исходной физикой

До правки сохранены PhaseEnthalpy.hlsli, PhaseTransitions.hlsl и
ThermalDiffusion.hlsl. Для контрольного запуска они подставлены в отдельную
копию runtime с теми же новыми параметрами/диагностикой. Это сравнение
механизма, не запуск полностью прежней версии игры.

Старые шейдеры проваливают те же проверки: ice10 мгновенно становится водой,
энергетический остаток+312.4; water−10 замерзает с остатком−312.6;
полный прогресс плавления при0°C игнорируется. Новый результат проходит.
[Baseline](../artifacts/ice-fusion-20261003/baseline/run.log).

Старые тесты полной конверсии получают заранее оплаченный прогресс и
достаточное тепло для трёх фаз. Их клетки-ограждения изолированы только
в диагностике, чтобы ограждение не вводило неизвестное Q между фазовыми
checkpoint. Реальный контакт с производственными параметрами измерен I02.
Проверка неподвижных клеток учитывает float-округление T; CO₂ в сценарии
движения может отдавать небольшой Q воздуху, остальные поля совпадают точно.

## Воспроизведение и границы

После `dotnet build Phyxel.sln -c Debug`:
`Diagnostics/RunIceFusion.ps1`, `Diagnostics/RunCorePhaseAcceptance.ps1`,
`Diagnostics/RunThermalDevices.ps1 -DevicesOnly`.
CPU-проверки: `PHYXEL_VERIFY_WORLD_CODEC`, `THERMAL_MATERIALS`,
`COMBUSTION_MATERIALS`, `THERMAL_DIFFUSION`, `PHASE_MATERIALS`,
`PHASE_RUNTIME`, `GAS_BRUSH` — с полным префиксом `PHYXEL_VERIFY_` и значением1.

Фаза остаётся одной целой клеткой до полной оплаты. Нет расширения льда,
плавучих ледяных тел, переохлаждения/зародышеобразования, солёности и
зависимости плавления от давления. Тепловой инструмент задаёт температуру
как внешний источник; он не отменяет уже накопленный фазовый прогресс.
Следующий отдельный пункт этапа1 — металл ↔ расплав с явным составом/масштабом
энергии в паспорте.
