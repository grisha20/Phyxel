# Подготовка к первому запуску — 2026-10-08

Связанный [контракт](STARTUP_CONTRACT.md). Артефакты —
`artifacts/startup-20261008/` (не входят в Git).

## Причина и изменение

Раньше `PhyxelGame.LoadContent` синхронно вызывал `PrepareSimulation`,
а тот — 85 вариантов вычислительных шейдеров. Отсутствующий кеш запускал
`D3DCompile` на потоке игрового окна. Главный дорогой этап —
`CellularAutomataSolver.hlsl/CSMain`: новый запуск без кеша воспроизводит
многоминутную работу компилятора с памятью около 810 МБ. Это соответствует
типу симптомов на присланном снимке, но компьютер брата здесь не измерялся.

Теперь build/publish подготавливает 85 DXBC-программ, исходные HLSL и
entry points проверяются по `ShaderCatalog`. Файлы с контрольными суммами
лежат в `Content/CompiledShaders`; весь каталог занимает 2 662 344 байта
(85 `.cso` + 85 `.sha256`). Байткод переносим между компьютерами с
поддерживаемым D3D11 устройством. Требования самого движка не менялись:
клеточный шейдер использует более восьми UAV, тест устройства использует
Feature Level 11.1, как существующий игровой путь.

Полный развёрнутый исходник и entry point по-прежнему определяют ключ
`phyxel-compute-shader-v1`; `cs_5_0`, OptimizationLevel3 и код физики прежние.
Готовый пакет проверяется раньше кеша. Неверная сумма/структура DXBC,
старый исходник или отсутствующий файл переходят к кешу/компиляции.
Кеш сохраняется атомарно; запись необязательна для запуска.

Если компиляция всё же нужна, сначала запускается отдельный WinForms
message loop, а один рабочий поток готовит только байткод. Никакой D3D11
контекст не переносится между потоками. Счётчик относится к количеству
программ, а не к доле времени: один клеточный шейдер может занимать большую
часть подготовки. Отмена закрывает окно без ожидания нативного компилятора;
ошибка оставляет читаемое объяснение и путь к журналу.

В настоящем холодном fallback первые 23 программы завершились примерно

## Повторение и распространение

```powershell
dotnet build Phyxel.csproj
dotnet publish Phyxel.csproj -o <папка-распространения>
```

Раздавать нужно **всю выходную папку**, включая `Content/CompiledShaders`,
Content, Materials и библиотеки. `SkipShaderPackaging=true` предназначен
для разработки и не нужен при распространении. Бинарные файлы генерируются
при сборке; они не коммитятся в репозиторий.

```powershell
$env:PHYXEL_VERIFY_STARTUP='1'
$env:PHYXEL_ARTIFACT_DIR='<отдельная-папка-результатов>'
# Для полной многоминутной fallback проверки:
$env:PHYXEL_STARTUP_COLD='1'
# Диагностический лимит по умолчанию 600 с; превышение/отмена даёт код 2
# и INCOMPLETE, а не PASS. Для изменения лимита:
$env:PHYXEL_STARTUP_COLD_SECONDS='600'
./Phyxel.exe
```

Для обычного старта с изолированным пустым кешем:
`PHYXEL_SHADER_CACHE_DIR=<новый-каталог>`; для отсутствующего пакета можно
переопределить `PHYXEL_SHADER_PACKAGE_DIR`. Диагностика не удаляет реальные
пользовательские файлы. Для автоматического первого кадра можно задать
`PHYXEL_UI_SCREENSHOT_PATH`, `PHYXEL_WINDOWED=1` и размеры окна.

Журналы обычного запуска:
`%LOCALAPPDATA%/Phyxel/Logs/startup-<дата-время>-<pid>.log`.
По ним различимы пакет/кеш/начало и конец компиляции, этап открытия D3D11,
готовность контента и первый кадр. Ошибки включают подробный stack trace.

## Границы

Три секунды — замер этого компьютера, не гарантия для компьютера брата.
Тесты отзывчивости и настоящая fallback компиляция не доказывают отсутствие
ошибок конкретного драйвера. Компиляция изменённого/неполного пакета остаётся
дорогой, но видимой и отменяемой. Подготовка байткода теперь оплачивается
разработчиком при сборке, а не каждым игроком на первом запуске.

В этом этапе не менялись физика, потоки, давление, частоты или сохранения.
Жалоба на FPS и зрелищность взрыва остаётся актуальной, её нельзя закрывать
измерением времени запуска.
