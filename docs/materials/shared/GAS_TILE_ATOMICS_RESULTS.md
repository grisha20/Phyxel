# GT: маска газа и полный кадр

2026-10-08, RTX4070, baseline d091668; [контракт](GAS_TILE_ATOMICS_CONTRACT.md).
Итог: оптимизация маски принята по точности и стоимости плотного газа.
Стабильные100FPS и устранение пользовательских32FPS не достигнуты/не доказаны.

GasActiveTiles объединяет9global записей каждой газовой клетки в9записей
одной группы16×16. Tile64, halo, checkerboard,8подшагов и частоты прежние.
Оба group barrier проходят крайние потоки за пределами мира.

12GPU-масок empty/boundary/sparse/dense×320×180/968×564/131×129 совпадают
с исходной CPU-формулой. В парном запуске старый и новый shader чередуются
в одном процессе, маски также совпадают GPU↔GPU. Существующий
GasTileRegressionVerifier:2режима×16тиков, Grid/Motion/CellMaterials byte exact
между маской и полным сканированием. PASS.

Парный микрозамер (мс за классификацию,20batch×20повторений):

|968×564|Старый|Новый|
|---|---:|---:|
|Пусто|.024352|.028794|
|Граница tiles|.024428|.028814|
|Редкий газ|.030149|.054918|
|Плотный газ|1.966690|.030591|

В плотном случае≈64раз быстрее; для редкого газа есть небольшой абсолютный
overhead барьеров. Это скорость одного прохода, не всей игры. Отдельные
ранние запуски менялись при смене порядка/нагрузки, потому основной вывод
основан на чередовании shader в одном процессе.

Настоящий Update/Draw/Present: копия пользовательской печи968×564,
2560×1440,30реальных секунд, датчики включены, разрушениеoff, окно
диагностического процесса скрыто. CPU замеры5..29с; GPU цифры — накопленные
асинхронные интервалы к концу прогона, включают возможные промежутки
подачи команд, не сумма исключительно активного времени shader.

|Запуск|FPS5..29с|Полный GPU-интервал,мс|Dispatch GPU,мс|Draw GPU,мс|CPU Present,мс|

|Старый1|69.34|12.840|12.083|.100|14.039|

|Старый2|70.58|10.603|10.407|.101|13.788|

Порядок старый1→новый1→старый2→новый2, один shader отличается через
opt-in diagnostic override, остальные данные/код одинаковы. Полный GPU
интервал сокращён примерно на16–21% в этих парах. Рост FPS мал и нестабилен;
CPU Update≈.21–.22мс, Draw≈.15мс, долгое ожидание в Present сохраняется.
Present может включать ожидание GPU/очереди/вывода; конкретная причина
его13–14мс пока не установлена. Видимое обычное окно и пользовательские32FPS
этим скрытым replay не воспроизведены. Не объявлять синхронизацию/DWM/
троттлинг причиной без дальнейших измерений.

Во всех6полнокадровых запусках физическое время≈1.000×, воздух/газ/реакции
≈60Hz, тепло≈20Hz. Никакого пропуска расчётного времени или снижения
итераций проекции не применялось. Принятая тяга подтверждена отдельным
30с GPU replay: [RF04](../tnt/RADIAL_FRONT_RESULTS.md).

Диагностика:

- `PHYXEL_FRAME_TRACE=<csv>`: CPU Update/Dispatch/Draw/Present и GPU frame/
  dispatch/draw; по умолчанию выключена, без blocking GPU readback/Flush.
- `PHYXEL_PROFILE_GAS_TILES=1`:12масок и микрозамеры;
  `PHYXEL_GAS_TILE_REFERENCE_SHADER=<старый .hlsl>` добавляет парное сравнение.
- `PHYXEL_GAS_TILE_OVERRIDE_SHADER=<старый .hlsl>` только для контролируемого
  baseline полного кадра; обычный запуск использует установленный shader.
- `PHYXEL_VERIFY_GAS_TILES=1`: прежняя проверка полного движения.
- Realtime fixture/clock: инструкции в RS и
  [FramePerformanceTrace](../../../Diagnostics/FramePerformanceTrace.cs).

Артефакты `artifacts/tnt-front-20261008/`: tiles-paired/run.log,
tiles-motion/run.log, frame-old/new-1/2/{clock,frames}.csv,
performance-analysis.json. Исходный shader для сравнения взят из d091668;
пользовательские сцены не перезаписывались. Следующая задача FPS — отделить
стоимость расчётов и ожидания вывода в обычном окне и воспроизвести32FPS.
