# CG: кислородный перенос и стабильный дым, 2026-10-09

[Контракт](COAL_GPU_CONTRACT.md). Исходная версия `9d26e9b`, Release,
RTX4070/D3D11. RTX3050 пока не измерена этим тестом. Присланные
`measurements (2).json`/`run (2).log` совпали с прежними 28 GW checks;
startup с102программами показал первый кадр2,322с, без компиляции.
Это не новая проверка текущих CG изменений и не профиль полосы угля.

## Причины и изменения

Simulation дополнительно переносит конечный O₂. Его проекция делала
64 глобальных Jacobi прохода каждый шаг и1024 при восстановлении scratch.
Теперь четыре прежние итерации выполняются одним запуском: output16×16,
halo4, shared tile24×24. Порядок суммирования, количество итераций,
преграды/фильтры, границы, поток и концентрация сохранены. Старый путь
доступен через `PHYXEL_OXYGEN_REFERENCE=1` для сравнения в одной сборке.

FireGlow гасился после показа, и промежуточные кадры читали уже потускневшее
поле. Это воспроизведено без шага физики повторной композицией. Новое
FireGlowPresentation хранит свежий отображаемый слой между60Гц шагами.
Само накопление/затухание/размытие прежние; отдельная копия не участвует
в горении, температуре или движении. Дополнительная память при1920×1080
около2,1МБ; копирование только при обновлении поля/перестройке паузы.
Очистка/загрузка/стирание на паузе перестраивают и отображаемый слой.

Нет новых коэффициентов материалов, изменений физического времени,
формата Grid/сцен или уменьшения точности при просадке. Пользовательские
сохранения не изменены.

## A/B на одном GPU

Точная сцена Гриши отсутствует. Замена: прогретая600°C полоса древесного
угля,75% ширины поля, глубина height/80, открытые края,15с реального времени.
Это более тяжёлая искусственная нагрузка; её FPS нельзя подставлять
вместо показаний Гриши. Сравнение исходного/нового кислородного пути в
одной сборке, оба используют исправленное отображение. Рендер ограничен
обычным100FPS pacer, физика идёт от реального elapsed.

| Поле/режим | Горение, GPU мс до → после | Render FPS до → после | Физическое время/реальное до → после |
|---|---:|---:|---:|
| 960×540 Simulation | 1,333 → 0,960 | ≈100 → ≈100 | 1,000 → 1,000 |
| 960×540 Sandbox | 0,200 → 0,183 | ≈100 → ≈100 | 1,000 → 1,000 |
| 1920×1080 Simulation | 11,848 → 4,963 | 12,34 → 17,31 | 0,613 → 0,845 |
| 1920×1080 Sandbox | 0,585 → 0,585 | 31,73 → 32,58 | 0,681 → 0,685 |

Артефакты: `artifacts/coal-20261009/capped-{reference,current}-{50,100}/`.
GPU ms — timestamp-выборки; FPS вычислен по frame.csv после4с,
physical rate — clock.csv после прогрева. Это разные интервалы наблюдения.
Рисование GPU около0,063–0,065мс; в Simulation дорого вычисление.
На полном поле горение дешевле примерно в2,4раза, но **100FPS и нормальный
темп физики ещё не достигнуты**. Газовый перенос/тепло/межшаговые расходы
остаются. Незначительные колебания Sandbox не приписываем кислородной
оптимизации: этот режим её не использует.

Первые `baseline-*`/`after-*` были без ограничения FPS; на50% получались
сотни промежуточных кадров. Они не заменяют приведённую capped серию.

## Свежие проверки

- 58 CG GPU checks PASS на итоговой сборке:36 побайтных сравнений
  4/64/1024 итераций на131×129,480×270,1920×1080, с maze/isolated/
  boundary/open;12 полных сравнений faces→projection→flux→transport→consume,
  включая ненулевой расход, фильтры, открытые/закрытые края, cold/warm solve.
  Сравниваются потенциал, O₂, доступный O₂ и flux. Private промежуточный
  scratch другой, итоговое физическое поле побайтно то же.
- Отображение дыма/пламени при30/60/100: повторная композиция без шага
  физики побайтно сохраняет PNG и Grid. Старый путь в том же тесте
  воспроизводит расхождение. Перестройка после стирания на паузе PASS.
- Свежие sparse/dense smoke_render, с эффектами и без:4 acceptance PASS.
- CoalFire с воздухом100FPS: поджиг/частичное выгорание древесного и
  каменного угля, продолжение после снятия огня, закрытая CO₂ камера PASS.
  CharcoalUsed121,645; StoneUsed42,042; CO₂ fuel mass2396→2396.
  Это игровые количества, не СИ/полная химия.
- Исходная сухая печь «Проверка тяги и темпиратур»: два режима по30
  логических секунд, просмотр пути пламени/дыма,8 snapshot save/load
  с датчиками и полями PASS. JSON/world защищены проверкой хешей.
- Debug/Release:0 ошибок/предупреждений. Готовый пакет108шейдеров;
  fresh startup121checks PASS, D3D11 загрузил все108 из пакета без компиляции.

`kernels16/` и portable wrapper kernels содержат58checks; `smoke-*`,
`coal-fire`, `furnace-{Simulation,Sandbox}`, `startup` — итоговые проверки.
Все артефакты игнорируются Git. Старые проверки не заменяли новые.

## Проверка на компьютере Гриши

В сборку входят `Profile-Coal.cmd/.ps1` и Diagnostics/RunFirePerformance.ps1.
Закрыть игру после сохранения сцены, запустить Profile-Coal.cmd рядом
с Phyxel.exe. Он проверит58GPU сценариев и выполнит A/B полосы угля на50/100%
в обоих режимах; обычное время около2–3минут, на слабом GPU может быть дольше.
Результаты: `%LOCALAPPDATA%/Phyxel/Benchmarks/Coal-<дата>-<pid>/`.
Передать всю папку: measurements.json, frame.csv, clock.csv, run/error logs.
Никакие пользовательские сцены не открываются и не переписываются.
Проверен запуск portable helper из Windows PowerShell5.1, scale50%,10с;
58checks PASS и четыре profile запуска завершились с физической rate≈1.

Полная приёмка паспортов, всех горючих пар и всех причин мерцания не
заявляется. Этот тест исправляет конкретную смену фазы свечения между
кадрами. На RTX3050 требуется новый профиль, не повтор прежнего GW теста.
