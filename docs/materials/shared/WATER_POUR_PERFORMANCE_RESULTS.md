# WP: заливка большой кистью — результаты 2026-10-09

[Контракт](WATER_POUR_PERFORMANCE_CONTRACT.md). Исходная физика ddc1495,
ветка codex/gas-motion-and-rendering. GPU здесь RTX4070, драйвер32.0.16.1088;
это не замер RTX3050 брата и не доказательство FPS с его компьютера.

## Причина и изменение

Общий PL-проход выполнялся120Гц одним GPU-потоком: последовательно обходил
все столбцы, доказывал поддержку каждого бассейна и до8 раз искал его
экстремумы. Большая заливка резко увеличивала стоимость. В фазе58 было
7.31мс в среднем/19.35максимум (включает вязкий проход и PL); отдельный
замер PL после первой частичной оптимизации всё ещё показывал около5мс.

Теперь поддержка/тип/скорость поверхности измеряются параллельно по
столбцам непосредственно на этом тике; каждый начальный связный бассейн
имеет своего владельца,64 потока совместно выбирают экстремумы. Выбор
краёв плато,8 последовательных переносов,120Гц, часы масла, преграды,
Mass/энтальпия/газовый пакет прежние. Кеш обновляет готовность обоих
затронутых столбцов, границы владельцев остаются неизменными до следующего
тика. Буфер временный,12 байт/столбец; сохранения не менялись.

Функции соседнего/широкого/местного/вязкого уровня13/56/57/58 компилируются
отдельными entry points из существующего CellularAutomataSolver, с прежними
16×16 потоками. Основной шейдер и его алгоритмы не переписаны. Reference
entry сохранён для A/B, упаковка включает все97 программ. Температурные,
кипящие и паровые обработчики, JSON материалов не менялись.

## Прямое до/после

RunWaterPour.ps1 подаёт настоящую удерживаемую кисть radius33/density.82
в правой свободной области копии большой горячей печи968×564/scale.5.
Подача1–7с, отпускание до10с. A — исходные функции/reference PL;
B — оптимизация, тот же исполняемый файл/сцена/шаг. Первый1с до заливки
исключён из статистики GPU: он включает подготовку нового D3D-контекста.
GPU timestamps асинхронны, без Flush; readback/PNG снаружи интервала.
Здесь измеряется compute, не общий FPS и не время отдельных игровых кадров.

холодная струя к2с достигает310, к7с —563, к10с источник очищен до205.
Обычное падение всё ещё зависит от кадров: отдельные физические часы воды
не введены. Просадка замедляла его и создавала впечатление густой воды;
коэффициент вязкости для устранения нагрузки не подменялся.

Полные снимки длительных A/B не совпадают побайтово даже без воздуха.
Контроль reference→reference также различается:54 клетки к1с,71231 к5с,
73786 к10с. Причина недетерминизма полной последовательности здесь не
установлена. Поэтому полный-мир byte-exact PASS не заявляется; точная
эквивалентность подтверждена прямыми проходами на одинаковых входных
буферах, а целое наблюдаемое поведение — отдельными критериями выше.
Это выбранные проверки, не полные паспорта/вся матрица взаимодействий.
