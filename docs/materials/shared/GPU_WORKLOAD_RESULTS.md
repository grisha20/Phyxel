# GW — нагрузка GPU после отзывов RTX 3050, 2026-10-08

[Контракт](GPU_WORKLOAD_CONTRACT.md). Исходная версия `496a88f`, ветка
`codex/gas-motion-and-rendering`. Замеры здесь **RTX 4070 / D3D11**;
цифры брата на RTX 3050 — отдельные пользовательские наблюдения в контракте.
На момент первого этапа 3050 ещё не была измерена; присланные позднее
результаты GPU теста добавлены ниже. Чужих изменений при старте не было.

## Причины и выполненный этап

При включённом разрушении граф замкнутых полостей перестраивался на каждом
60-Гц шаге даже у холодной неподвижной оболочки. Построение рёбер заново
сканировало fine-преграды; затем выполнялись восемь union/compress.
Это существенная самостоятельная стоимость переключателя до поджига.

Теперь GPU сравнивает всю маску эффективных препятствий, включая фильтры,
с предыдущей. Неизменная маска позволяет использовать прежние roots/links;
изменённая запускает прежнее полное решение через indirect dispatch.
При движении твёрдых клеток статистика может сразу выбрать полное
перестроение без дополнительного сканирования. Эта задержанная подсказка
**никогда не разрешает reuse**: его разрешает только точное сравнение масок
на текущем шаге. Полное перестроение инвалидирует кеш. Clear, загрузка/
восстановление активности и новые ресурсы также инвалидируют его.
Добавлена память маски: четыре байта на fine-клетку, ≈2,1 MiB на 968×564.
GPU аргументы копируются в отдельный 28-байтовый indirect буфер; readback
для выбора ветки в игре отсутствует.

Воздушная коррекция выполняла 128 самостоятельных GPU запусков Jacobi.
Теперь четыре итерации объединены в tile 16×16 с halo четыре клетки,
выходом 8×8 и общей памятью группы: **128 итераций в 32 запусках**.
Вход и выход глобально разделены; порядок суммирования соседей, clamp,
непроницаемые/открытые границы и частота физических часов прежние.
Итоговый `ProjectionA` побайтно совпадает. `ProjectionB.x` теперь содержит
итерацию 124 вместо 127: это scratch, не используемый итоговым CSProject
или сериализатором; divergence `B.y` совпадает. Формат Grid56/Material244/
writer19 прежний, JSON материалов не менялись.

Отвергнута первая версия с пересчётом всех рёбер перед проверкой: она
сохраняла основную стоимость. Не уменьшались частоты, масштаб, разрешение
воздуха, число итераций, прочности, тепло, скорость горения или выброса.
CUDA-перенос не входит в этап: вопрос брата был ознакомительным.

## Производительность и ограничения

Финальный Release пакет, запущенный через `Profile-GPU.ps1` в Windows
PowerShell 5.1: 28 проверок PASS. Время отдельных GPU участков, мс:

| Fine-размер | Граф полный → кеш, неизменная геометрия | Jacobi128 open, старый → новый |
|---|---:|---:|
| 131×129 | 0,186 → 0,022 | 0,221 → 0,132 |
| 480×270 | 0,496 → 0,026 | 0,245 → 0,137 |
| 968×564 | 2,114 → 0,188 | 0,325 → 0,188 |
| 1920×1080 | 19,776 → 0,784 | 0,596 → 0,440 |

Это **kernel timing, не ускорение всего кадра или прогноз FPS 3050**.
Замеры последовательные, старые и новые программы в одном устройстве.

Обычные Update/Draw/Present в окне 2560×1440, Simulation, разрушение
включено, 10 с wall-clock; первые две секунды исключены из FPS, GPU
средние — начиная с 3 с. Холодная синтетическая оболочка 968×564:
полный GPU кадр 5,21 → 3,98–4,32 мс, граф 2,30 → 0,20–0,21 мс.
FPS обоих вариантов ограничен 100: это не доказательство отсутствия
просадки на слабой карте. Финальный повтор использует подсказку движения.

На сохранённой TNT-бомбе разброс велик: финальные два reference прогона
80,81/85,75 FPS, current 96,11/80,74 FPS; GPU кадр соответственно
9,75/10,54 и 8,63/9,32 мс. Есть перекрытие диапазонов FPS, **стабильное
ускорение целого взрыва не доказано**. Во всех этих замерах отношение
simulationSeconds/wallSeconds ≈1,0000: время не замедлялось ради FPS.

Синтетический пустой мир с сохранённым горячим воздухом 550°C:
2,90 → 2,78 мс GPU кадра, оба 100 FPS. Это **не точное воспроизведение
брата после стирания кистью**, дефект 23–27 FPS после стирания не закрыт.
Остаточный воздух/тепло не удаляются оптимизацией. AirStage counters=0
в realtime trace без специального флага означают отсутствие замера,
а не отсутствие воздушной работы; их нельзя суммировать как полный профиль.

## Полученный тест брата — RTX 3050, 2026-10-08

Пользователь передал `measurements.json` и `run.log` и сообщил:
«стало получше, но всё же просадки». Лог подтверждает NVIDIA GeForce
RTX 3050, vendor 0x10DE / device 0x2507. Вариант VRAM и FPS его сцены
этими файлами не определяются. **Все 28 проверок PASS**, включая 16
побайтных сравнений Jacobi и проверку графа/indirect аргументов.

| Fine-размер | Полный граф → кеш, мс | Ускорение участка | Jacobi128 open, мс |
|---|---:|---:|---:|
| 131×129 | 0,235 → 0,035 | 6,7× | 0,261 → 0,161 |
| 480×270 | 0,915 → 0,117 | 7,8× | 0,310 → 0,183 |
| 968×564 | 14,452 → 0,479 | 30,2× | 0,630 → 0,428 |
| 1920×1080 | 110,146 → 1,787 | 61,6× | 3,551 → 1,387 |

На 968×564 Jacobi open/blocked/isolated/maze сократился на 20–32% по
среднему времени. У open/maze baseline были единичные длинные измерения:
около 1,06 мс против minimum около 0,54; не считать максимум устойчивой
нагрузкой. Samples Jacobi=6, графа=10: это короткий сравнительный тест.

Ускорение графа относится к **неизменной геометрии**. При движении стен,
осколков либо непроницаемых жидкостей требуется полное перестроение;
30× не является множителем FPS игры. Файлы не измеряют целый кадр,
горение/лучевой теплообмен, движение частиц, вывод и CPU ожидания.
Причина оставшихся просадок конкретной сцены поэтому **не установлена**.
Следующий профиль должен снять обычную проблемную сцену во время движения,
с разрушением on/off, по стадиям GPU и Update/Draw/Present. Сцену брата
в этих вложениях пользователь не предоставил; физика не перенастраивалась.

SHA256 присланных оригиналов, которые не изменялись:

- measurements.json: `7F3536268F1D270D65EA4976556CC9125D3BF30452224272CCC3AE95031DE31E`;
- run.log: `0D83ECDE24D81C7B5936821783E9995D2B047AB29E2BCC37BA164A7FCD7CC71E`.

Копии сохранены вне Git в `artifacts/gpu-workload-20261008/rtx3050/`.
Сборка и игровые проверки не повторялись: этот этап только фиксирует
и анализирует новые внешние замеры.

CUDA: в локальном коде физика уже выполняется через D3D11 ComputeShader /
Dispatch. На NVIDIA эти вычисления выполняют те же GPU мультипроцессоры,
которые используются CUDA; отдельного неиспользуемого набора «CUDA ядер»
для включения нет. Иной API может открыть иные возможности оптимизации,
но выигрыш требуется измерять на алгоритме, он не следует из смены названия.
Новый backend не был поручен. Контекст: [NVIDIA DirectCompute Guide](https://developer.download.nvidia.com/compute/DevZone/docs/html/DirectCompute/doc/DirectCompute_Programming_Guide.pdf),
[CUDA programming model](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html).
