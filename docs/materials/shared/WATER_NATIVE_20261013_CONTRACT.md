## Кандидат до реализации

Он до8/4 раз повторяет чтение top/base, материала и готовности каждого

в groupshared-памяти; после каждого удачного переноса обновлять оба

вместо64 для скрытия задержек широких gather; это не изменение числа
переносов. Общий CellularAutomata оставить эталоном коротких сравнений.

## W13c — доказанно закрытые источники carrier, до правки

AirThermal.ExchangeNode для каждого занятого негазового пакета пробует
четыре соседние точки. AirFineNodeFor перебирает до9 узлов даже когда
сама начальная точка закрыта водой/твёрдым телом; любой AirFineSegmentOpen
немедленно отклоняет такую точку. В глубине ванны это десятки повторов
одного и того же доказательства на каждую клетку каждого60Hz тика.
Вызвать AirFineBlocked один раз перед поиском: закрытый start не может
иметь видимого узла. Открытые точки сохраняют прежний поиск, выбранный
узел, SurfacePhase, коэффициенты и E/C. Общий FineAirGeometry не менять.
Добавить opt-in старого пути для прямого побайтного сравнения Grid,
AirThermal и flux при всех четырёх фазах поверхности, горячей/холодной
ванне, стене/узком канале/фильтре/слоях/газах. Проверить существующий
баланс AirHeat и печь; не менять геометрию/подачу/расход топлива.

## W13d — пустой поиск целей и повтор одного донора, до правки

## W13f — общие атомарные счётчики статистики, до правки

RenderComposition.Collect на каждом10-м кадре делает2..4 global
InterlockedAdd на каждую активную клетку в одни адреса Statistics[0].
В ванне1.36млн клеток это миллионы конкурирующих atomic-операций;
счётчики нужны также для сна физики, поэтому отключать/прореживать их нельзя.
Сначала суммировать девять целочисленных счётчиков внутри16×16 группы,
затем один владелец добавляет её итоги в общие поля. FrameIndex и три
диагностических поля записывает прежняя клетка0. Сохранить период10,
точные определения resting/moving/kinds/free-body и все пиксели.
Барьер помещать во внешней обёртке: граничный поток/ранний выход
рендера всё равно должны встретить барьер группы. Air debug сохраняет
прежнее отсутствие Collect, без расширения этой задачи.
Сравнить исходный CSReference с новым CSMain по полному Statistics и
текстуре в трёх display-режимах, collect off/on, разных типах/движении,
фильтрах, неполных16×16 крайних блоках. Повторить парный полный replay
с буферизованными timestamps. Модель/механизмы печи не менять.

## W13g — короткие групповые редукции, до правки

Промежуточный полный замер сохраняет FAIL15%: улучшение пока лишь3..5%.
Grouped Collect совпал по72 текстурам/счётчикам, но крупного выигрыша
целого кадра от него не видно. Не выдавать гипотезу о нём за доказанный
главный bottleneck. LeanTimings исключил влияние множества query:
14.884→14.433мс; ванна20.150→19.410мс. Критерии не ослабляются.

В основном поиске ParallelSurface каждая редукция64 lanes делает шесть
последовательных барьеров дерева, несколько раз на перенос8/4. Заменить
их shared integer atomic min/max/and с меньшим числом барьеров:
донор выбирается ключом top*(Width+1)+left, правый край остаётся max;
цель ключом (Height-top)*(Width+1)+distance, затем minX при равном ключе.
При разрешённых размерах ключ не переполняетuint. Два булевых доказательства
пути свести shared AND; границы препятствий — shared min/max. Сохранить
все tie-break/порядок, исходный точный fallback и глобальные буферы.
После изменения — прежнее побайтное сравнение фаз, затем полный A/B.

W13f/g отклонены после замеров: групповые счётчики и shared-atomic
редукции прошли побайтные проверки, но не дали заявленного ускорения.
Их изменения удалены. Неверно объявлять глобальные атомики главным
источником просадки по одному чтению кода. Сохранены только доказанные
ранние отказы и сокращение массива перемешивания; далее расширен профиль

## W13i — очередь ответов phase-summary, до правки

W13h дал13.622мс против14.856мс, цель ещё FAIL. Узел причин:
три4-байтовых readback-slot заполняются быстрее, чем GPU исполняет
пакет команд; fallback включает все виды каталога/геометрию/газы.
Увеличить кольцо до32 slots, сохранив немедленный DoNotFlush polling
каждого готового ответа, generation guard и прежний fallback, если
заполнено даже это кольцо. Никаких CPU waits/Flush, отбрасывания
событий или замены физики. Это запас ёмкости очереди, не задержка
получения готового события. Добавить диагностический размер3 для
парной проверки и прежней намеренно переполненной phase-acceptance;
проверить оба размера на том же воспроизведении воды и реальных
переходах/пробуждении. Оценить полный compute, не только отсутствие
fallback; при нарушении переходов кандидат отклонить.

W13i отклонён до реализации: увеличение ёмкости откладывает момент
защитного пробуждения, если реальный переход уже произошёл, а его
ответ ещё в очереди. Для этапа без изменения физики это неприемлемый
обмен точности на FPS. Кольцо остаётся3; нужна GPU-классификация
ненужной работы, а не ослабление гарантии пробуждения.
