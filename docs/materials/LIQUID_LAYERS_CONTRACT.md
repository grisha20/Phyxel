# LL: округлая чаша и вода под маслом — 2026-10-05

Задача: масло удерживает горку без гидравлики, а граница water/oil
остаётся выгнутой в обоих режимах гидравлики. Точного сохранения нет;
сценарий воспроизводит округлый сосуд и отдельные слои, не точные пиксели.
Исходная версия `04f7b7c` проверяла только плоское основание масла.

Прочитаны паспорта oil/water и локальные TPT OIL.cpp, WATR.cpp,
общие движение жидкости Simulation.cpp 3130–3220, взаимодействие
воздуха 2335–2375. TPT имеет Falldown=2, боковой поиск и плотностный
обмен; отдельная опциональная flood_water не равна обычному движению.
Игровые Weight/Gravity не переносятся как СИ. Реальные новые фазовые
числа в этом этапе не назначаются: выбранная модель масла остаётся
n-гексадеканом с плавлением 18 °C. Повышение начальной температуры
не заменяет выравнивание границы жидкостей.

До физической правки:

- LL01: округлая чаша, ширина 300 клеток, масло 20/30/40 °C.
  Через 30 с перепад открытой поверхности в центральных столбцах140–320
  ≤2 клетки при гидравлике off/on, Sandbox/Simulation, 30/60/100 FPS.
- LL02: та же чаша, вода под более лёгким маслом, начально выгнутая
  граница. Через 30 с перепад свободной поверхности и границы в этих
  столбцах ≤2 клетки, без включения обязательной гидравлики.
  20/30 °C, те же режимы/FPS. Не требовать мгновенного перестроения.
- LL03: замкнутая перегородка между двумя смесями не пропускает
  массу; каждый ID сохраняет массу с абсолютной ошибкой <1e-4,
  общий Q с относительной ошибкой <1e-5; стенки остаются на месте.
- Дополнительно: местная подача масла на воду остаётся местной,
  прежние LT01 расход/температура/FPS не ослабляются, WL вода/лёд
  и OS плоская чаша проверяются по затронутым сценариям.

Механизм должен использовать kind/density/температурную мобильность,
а не runtime ID. Связность и проверка стенки обязательны. Передача
полного пакета Grid сохраняет индивидуальную массу и энтальпию.
При наличии верхней жидкости следует учитывать её вес при выборе
направления движения нижней границы. Объёмное выравнивание масла
через весь экран и телепортация струи не разрешаются.

Это ограниченная модель спокойных связных слоёв, не полноценный
решатель гидродинамики, капиллярности или смешиваемости всех жидкостей.
Состав и неподдерживаемая химия не меняются. PASS выбранных чаш
не означает выполнение паспортов целиком.

Пользователь выбрал начальные 30 °C для новых обычных материалов.
JSON начальной температуры co2/coal/fixture/gunpowder/metal/oil/sand/
stone_coal/stone/water/wet_charcoal/wood и fallback загрузчика меняются
20→30. Лёд, застывшее масло, огонь, дым, пар, расплав и масляный пар
сохраняют специальные значения; heater/cooler — температуру устройства.
Сохранённые сцены не переписываются; температура фонового воздуха и
порог застывания не меняются. Это игровая температура создания,
не справочная константа веществ. Реальная кисть должна создать 12
обычных ID при30 °C и сохранить особые температуры остальных ID.

В очень старых v3/v4 температура отсутствовала: для прежних core
материалов миграция сохраняет исторические20 °C. v5–v14 с записанной
температурой читаются без замены. Внешние ID без такой истории используют
собственные настройки. Это проверяется прежним WorldCellCodec verifier.

Первый вариант LL01 прошёл при60FPS: масло в округлой чаше1–2 клетки
вместо9 без гидравлики. LL02 пока FAIL: граница4–5 клеток вместо14–17.
Порог≤2 не меняется. Допуск в целую клетку на каждом коротком участке
оставлял суммарный широкий изгиб; следующая версия допускает обмен при
одноклеточном перепаде, учитывая вес верхнего слоя, и чередует направление
просмотра плато. Итог должен быть измерен отдельно, не принят по коду.

Вторая версия: 71/72 PASS. Все границы слоёв LL02 — 1–2 клетки;
LL01 Simulation/off/30 FPS/30 °C оставил 3 клетки. Порог не ослаблен.
Следующая версия увеличивает бюджет локального выравнивания с 4 до 8
только над плавно наклонным опорным дном. Плоское дно сохраняет бюджет4,
резкие сливы и свободное падение исключены. Нужен повтор полной матрицы.

Третья версия с одним увеличением бюджета не принята: уже первые чаши
Sandbox/off/30 FPS/20–30 °C дали 3 клетки. Четвёртая версия проверяет
все допустимые донорские столбцы короткого участка над наклонным дном,
выбирая наибольший местный перепад. Ранее выбирались лишь два края
самого высокого плато: они могли не иметь цели в пределах8 клеток,
хотя соседние столбцы ещё должны были течь. Плоская опора использует
прежний выбор. Все численные критерии и 30 секунд сохранены.

Четвёртая версия тоже не принята: повторные обмены одноклеточного
напора внутри одного тика вместе с однонаправленным просмотром оставляли
ступени3 клетки. Пятая версия чередует просмотр доноров и выполняет
один обмен за проход над наклонной опорой, вместо8 повторов одного
участка. Срок/перепад/масса/Q прежние; плоская опора всё ещё4 обмена.
Третий и четвёртый прогоны остановлены после выявления FAIL;
их частичные логи не считаются завершённой приёмкой.

граница воды1–2 клетки; верхняя поверхность двух слоёв0. Масса/Q/
стенки/каждый ID по сторонам перегородки — ошибки0 в изолированной
