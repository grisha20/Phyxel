# Первый запуск и подготовка шейдеров — 2026-10-08

Проблема: `LoadContent → PrepareSimulation → CompileShader` выполняет
компиляцию десятков HLSL-программ на потоке окна. Пока компилятор работает,
Windows не получает ответы окна. Пользователь сообщил ожидание 3–10 минут
на другом компьютере; на этом компьютере это время ещё не воспроизведено.

Контракт этого этапа:

1. Build/publish готовит оптимизированный DXBC `cs_5_0` для всех штатных
   вычислительных программ. Игрок получает байткод вместе с игрой. Подготовка
   не требует GPU; исходники/entry point/OptimizationLevel3 прежние.
2. Выбор байткода зависит от полного развёрнутого исходника и entry point,
   включая shared include. Несовпадающий/повреждённый файл не используется.
   Готовый пакет имеет приоритет перед пользовательским кешем.
3. При недостающем пакете сначала открывается окно подготовки. Компиляция
   байткода выполняется на одном рабочем потоке; поток WinForms продолжает
   обрабатывать сообщения. GPU/контекст остаются на игровом потоке.
4. Показываются реальный счётчик программ, текущая операция и прошедшее
   время. Счётчик не называется прогнозом оставшегося времени. Можно закрыть
   подготовку без ожидания завершения нативного компилятора.
5. Ошибка не оставляет безымянное зависшее окно: объяснение, журнал и выход.
   Запись кеша атомарная; невозможность записи не препятствует запуску.
6. Измеряются запуск с пустым пользовательским кешем и готовым пакетом,
   повторный запуск, fallback без пакета, отзывчивость/отмена/ошибка,
   наличие байткода в publish и его загрузка реальным D3D11 устройством.

Физика, частоты расчёта и схемы сцен не меняются. Работа над FPS и
зрелищностью взрыва остаётся отдельным незавершённым этапом.
