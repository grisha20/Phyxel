# FP: FPS и равномерность вывода

2026-10-08, baseline 4ed22ef, RTX4070.
[Контракт](FRAME_PACING_CONTRACT.md). Физические шейдеры, частоты и материалы
в этом этапе не менялись; паспорта не получают новых физических статусов.

## Изменение

Обычный запуск теперь выводит кадры без VSync и ограничивает их100FPS
через Windows high-resolution waitable timer после Present. Следующий
GameTime включает ожидание. Малые задержки пробуждения компенсируются
сохранением дедлайна; после пропущенного периода расписание начинается
заново. Busy spin нет. При недоступном high-resolution timer — Sleep с
временно запрошенным разрешением1мс, освобождаемым при завершении.
На проверенной машине использован high-resolution timer; fallback здесь
не потребовался и отдельно не измерен.

Acceptance и ускоренные verifier с собственным расписанием не получают
второй limiter. Существующий100FPS диагностический spin в отдельных старых
verifier не переносился в обычную игру. Настройки сохраняемых сцен прежние.

## Контролируемое сравнение

Копия «Проверка тяги и темпиратур»:968×564, масштаб50%, десять датчиков,
2560×1440, Simulation, разрушениеoff. Каждый процесс30реальных секунд,
последовательные запуски, не одновременно. Анализ после прогрева5..29с.
Диагностические процессы запускались с WindowStyle Hidden; обычный
интерактивный сеанс пользователя этим не подменяется.

Обе пары дают рост среднего FPS примерно39–45%, p95 сокращается примерно
втрое. При прежнем VSync встречались интервалы≈30мс при медиане≈10мс.
Отключение этого пути убирает наблюдаемый ритм ожиданий; конкретную внутреннюю
причину в драйвере/композиторе не устанавливали. Долгое ожидание переносится
в предсказуемый таймер, вместо бесконтрольного рендера232FPS.

Физическое время во всех неприостановленных сравнениях≈1.000×,
воздух/газ/горение≈60Hz, тепло≈20Hz. GPU-интервал кадра зависит от количества
тиков в каждом кадре и подачи команд; уменьшение его среднего нельзя
выдавать за ускорение физического решателя — он здесь не менялся.

Первая кандидатная версия с дедлайном от начала каждого кадра давала94.41FPS:
накапливался overhead пробуждения. Принята версия с непрерывным дедлайном,
100.00FPS в двух независимых повторах.

## Воспроизведение и границы

`PHYXEL_VERIFY_FURNACE_SENSORS=1`, `PHYXEL_SENSOR_REALTIME=1`,
`PHYXEL_SENSOR_DESTRUCTION=0`, `PHYXEL_CLOCK_TRACE_SECONDS=30`,
`PHYXEL_SIMULATION_CLOCK_TRACE=<csv>`, `PHYXEL_FRAME_TRACE=<csv>`,
`PHYXEL_WINDOWED=1`, `PHYXEL_WINDOW_WIDTH=2560`, `PHYXEL_WINDOW_HEIGHT=1440`.
Обычные значения: VSyncoff/limit100. Контроль прежнего вывода:
`PHYXEL_FRAME_VSYNC=1` (без limiter по умолчанию); uncapped:
`PHYXEL_FRAME_LIMIT=0`. Для иных диагностических частот допустимы1..240.
`PHYXEL_SENSOR_PAUSED=1` сохраняет fixture на паузе;
`PHYXEL_SENSOR_MODE=Sandbox` переключает режим.
`pacingCpuMs` в CSV — время ожидания, не занятость CPU.

Артефакты: `artifacts/fps-20261008/`, парные `vsync-on-1/2`,
`paced-accepted-1/2`, контроль `vsync-off-1`, `performance-analysis.json`.
Пользовательскиеjson/world не перезаписываются. Точное длительное падение
до32FPS из пользовательского сеанса не воспроизведено;100FPS не обещаны
для произвольной сцены/оборудования. VSyncoff может допускать tearing при
непосредственном выводе; пользовательский визуальный сеанс после правки
остаётся отдельной проверкой. Новые эффекты взрыва этим этапом не добавлены.
